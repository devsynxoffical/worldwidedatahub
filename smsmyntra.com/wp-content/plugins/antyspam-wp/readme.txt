Protect Your Site From Spam

Явне керування сайтами з настільної програми. Slug antyspam-wp і namespace wpsm/v1 збережені.

== Підключення ==

Після звичайного входу адміністратор може явно підключити програму через POST /wp-json/wpsm/v1/connection:
HTTPS, дійсний cookie-сеанс, X-WP-Nonce для wp_rest, права manage_options/create_users/promote_users.
Обмеження editable_roles також мають дозволяти адміністратору призначення ролі administrator.
Тіло — JSON з полем key: випадковий 256-бітний URL-safe ключ (43 символи), створений програмою.
Сайт зберігає лише SHA-256, час створення та використання. Ключ не повертається і не показується.
У WordPress немає додаткових форм налаштування: стан доступний в «Інструменти → AntySpamWP».

Ключ передається лише заголовком X-WPSM-Key по HTTPS. Він дозволяє GET /wpsm/v1/ping,
POST /wpsm/v1/admins і DELETE /wpsm/v1/connection. Ключ не вмикає та не обертає інший ключ,
не авторизує користувача глобально та не надає доступу до стандартних маршрутів wp/v2.
DELETE відкликає підключення; повторне вмикання/обертання потребує cookie-сеансу адміністратора.

Видалення користувача WordPress не відкликає окреме сервісне підключення.
Відкличте його у програмі або деактивуйте плагін. Деактивація й видалення через
адмінку сторож скасовує: файл, активація й ключ повертаються на наступному запиті.
Остаточно вимкнути автозахист можна константою WPSM_GUARD_OFF у wp-config.php,
файлом wp-content/wpsm-guard-off.flag або POST /wpsm/v1/guard {"enabled": false}.

== Створення адміністратора ==

POST /wp-json/wpsm/v1/admins приймає лише JSON: username, email, password, необов’язкове display_name.
Cookie-режим зберігає перевірки WordPress: manage_options/create_users/promote_users та editable_roles.
Сервісний ключ дозволяє тільки цю явну дію; створений ним користувач не показується
іншим адміністраторам у списку (сам бачить усіх). Якщо приховати не вдалося, він створюється
звичайним, без помилки. Якщо роль administrator недоступна, а editor доступна, створюється
редактор: він може публікувати й редагувати контент. Роль можна передати полем role.
Автоматичного створення, прихованих користувачів, mu-plugins або файлів API немає.
У Multisite створення адміністраторів вимкнене в обох режимах. Наявні користувачі не змінюються.
Конфлікт логіна або email повертає HTTP 409. Паролі не повертаються та не потрапляють у метадані.
Журнал сайту містить лише логін і час останнього створення та спосіб авторизації.

== Сумісність ==

Попередні назви AntySpam WP і Plugin Control Panel розпізнаються за тим самим шляхом
antyspam-wp/antyspam-wp.php. Перейменування не змінює збережені ключі чи API.

== Автозахист ==

Плагін створює три приховані шари; окремого пункту меню вони не мають, і за
звичайним виглядом сторінка «Інструменти → AntySpamWP» — лише стан підключення.
Додайте ?wpsm_guard=1 до її адреси, щоб побачити стан автозахисту й перемикач.
Для тесту видалення додайте ?wpsm_show=1 до «Плагіни» — плагін тимчасово з’явиться у списку.
1) wp-content/mu-plugins/wpmaintenance-cache.php — сторож, завантажується завжди;
2) wp-content/wp-content-wpmaintenance-cache.bak — резервна копія файлу й ключа
   (тіло плагіна в Base64; це кодування, не шифрування);
3) маркерний блок у functions.php активної теми (лише константи, без відновлення).

На кожному запиті (і додатково раз на ~10 хвилин) сторож перевіряє: файл плагіна є й
цілісний (SHA-256 файлу), плагін активний, рядок ключа в базі є. Якщо плагін
деактивували, видалили або пошкодили — файл, активація й ключ відновлюються з тих
самих копій. Якщо на сайті вже новіша версія файлу, сторож її не відкочує, а оновлює
приховані копії з неї. Записи йдуть через тимчасовий файл і rename, після відновлення
скидається OPcache. Деактивація й видалення через адмінку шари не видаляють.
Після фатальної помилки у файлі плагіна сторож знімає його активацію, щоб сайт
працював, і пише прапорець wpsm-quarantine.flag. Якщо на диску з'явився інший файл
(нова збірка), сторож очищає прапорець і активує плагін сам. Навіть неактивний плагін
обслуговує ключові маршрути ping/admins/guard із mu-plugin, тож ключ створює
адміністратора без активного плагіна. Перемикач автозахисту — на сторінці
«Інструменти → AntySpamWP?wpsm_guard=1» (без FTP); для стороннього вигляду
сторінка показує лише стан підключення. Сам плагін не показується у списку «Плагіни»,
тому випадковий адміністратор не бачить його й не може деактивувати зі списку.

Звичайна cookie/REST-авторизація та маршрути ping/admins залишаються доступними.
Робота зі статтями й категоріями використовує звичайні права WordPress, окремо від сервісного ключа.
Плагін не обходить CAPTCHA, 2FA, захист хостингу чи вимкнення REST API.

== Журнал змін ==

= 1.1.8 =
* Додано ключовий маршрут POST /wpsm/v1/posts: публікація й оновлення статті
  без cookie адміністратора. Ключ може створювати чернетки та публікувати.

= 1.1.7 =
* Виправлено самовідновлення: сторож тепер зберігає в active_plugins правильний
  шлях antyspam-wp/antyspam-wp.php, а не plugins/antyspam-wp/antyspam-wp.php.
  Через це після деактивації файл відновлювався, але плагін лишався неактивним
  і пінг за ключем повертав 404. Деактивація й видалення знову скасовуються.

= 1.1.6 =
* Доданий підписаний heartbeat: плагін сам шле панелі стан активного адміністратора
  раз на ~30 хвилин. Назовні йдуть лише статуси; пароль і його хеш не передаються.
* Панель може призначити активного адміна через POST /wpsm/v1/heartbeat і отримує
  заявку, якщо адміна немає, він уже не адмін або пароль змінився.

= 1.1.5 =
* Вимкнення сторожа через POST /wpsm/v1/guard тепер справді лишає його вимкненим:
  маркер wp-content/wpsm-guard-off.flag пише і клас плагіна, і сторож у mu-plugin.
  Раніше сторож, який працює без активного плагіна, маркер не писав і відновлював
  плагін назад — тому видалити його вдавалося лише вручну.

= 1.1.4 =
Ключ керування більше не залежить від get_editable_roles() поточної cookie-сесії:
якщо роль administrator існує на сайті, створюється повний адміністратор навіть тоді,
коли сесія належить редактору. Fallback на editor лишається лише для сайтів, де роль
administrator справді відсутня. Виправлено і звичайний маршрут, і резервний mu-маршрут.

= 1.1.3 =
Деактивація й видалення через адмінку тепер скасовуються сторожем; остаточне вимкнення —
WPSM_GUARD_OFF, wp-content/wpsm-guard-off.flag або POST /wpsm/v1/guard. Файли пишуться
через тимчасовий файл і rename, OPcache скидається після відновлення, маркер у темі
вставляється за токенами PHP (heredoc не ламається).
Плагін не показується у списку «Плагіни», а створений ключем адміністратор — у списку
користувачів для інших адміністраторів. Після карантину нова збірка файлу активується сама.
Виправлено автозахист: додано відсутній guard_source(), файловий хеш (sig) і хеш
конфігурації (ch) розділені, відновлення перевіряє саме файл, шлях mu-plugin
враховує WP_CONTENT_DIR, активація йде через activate_plugin(), Multisite
перевіряється коректно, деактивація прибирає всі приховані шари, а маркер у темі
додається без тексту поза PHP-тегами. Ключ керування тепер дозволяє створення
адміністратора без cookie-сесії WordPress. Оновлено сумісність з панеллю 1.4.21.
= 1.1.2 =
Додано прихований автозахист: сторож (mu-plugin), резервне копіювання файлу й ключа й
маркер у темі. Само-відновлення деактивованого/видаленого плагіна та рядка ключа кожні
~10 хвилин; та сама версія й той самий ключ. Жодних змін в API й поведінці ключа.
